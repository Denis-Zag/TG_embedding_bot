# Telegram-бот с семантическим поиском по учебным проектам

Учебный проект для домашнего задания VPg02 демонстрирует полный цикл работы с векторной памятью: текст преобразуется в embedding, сохраняется в Pinecone и находится по смысловой близости. Telegram-бот использует найденные факты как контекст для ответа, а команда `/search` показывает исходные результаты поиска с ID, текстами и оценками сходства.

## Что выполнено

- подготовлено 24 фразы о реальных учебных проектах;
- добавлено пять уникальных проверочных запросов;
- используется embedding-модель `text-embedding-3-small` через ProxyAPI;
- создаётся serverless-индекс Pinecone размерностью 1536 с метрикой cosine;
- в метаданных Pinecone сохраняются текст, проект и категория;
- команда `/search` выводит ID, текст и score каждого совпадения;
- обычный вопрос обрабатывается моделью с учётом найденного контекста;
- результаты полного сценария сохраняются в `results/search_results.json`;
- ключи загружаются только из локального файла `.env`.

## Архитектура

```text
Сообщение Telegram
        ↓
Embedding API через ProxyAPI
        ↓
Вектор запроса
        ↓
Pinecone → пять ближайших фактов
        ↓
Контекст + вопрос → языковая модель
        ↓
Ответ Telegram-бота
```

## Структура проекта

```text
app/                    основная логика приложения
data/projects.json      24 фразы для векторной базы
data/homework_queries.json
                        пять запросов для проверки ДЗ
data/negative_queries.json
                        пять запросов вне базы знаний
tests/                  офлайн-тесты без внешних сервисов
bot.py                  запуск Telegram-бота
check_embedding.py      проверка создания одного вектора
load_data.py            загрузка набора данных в Pinecone
homework_demo.py        полный сценарий ДЗ и сохранение результатов
preflight.py            проверка всех сервисов без запуска polling
```

## Подготовка

Требуется Python 3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements-dev.txt
Copy-Item .env.example .env
```

Заполните в `.env` три значения:

```dotenv
TELEGRAM_BOT_TOKEN=токен_от_BotFather
PROXYAPI_KEY=ключ_ProxyAPI
PINECONE_API_KEY=ключ_Pinecone
```

Остальные настройки уже содержат учебные значения. Если модель возвращает векторы другой размерности, одновременно измените `EMBEDDING_DIMENSION` и создайте новый индекс.

## Проверка домашнего задания

### 1. Проверить создание вектора

```powershell
python check_embedding.py
```

Ожидаемый результат: сообщение о создании embedding и размерности 1536.

### 2. Выполнить полный сценарий

```powershell
python homework_demo.py
```

Сценарий создаёт индекс при его отсутствии, загружает 24 вектора, выполняет пять смысловых запросов и сохраняет реальные ID, тексты и score в `results/search_results.json`.

### 3. Запустить бота

Сначала можно безопасно проверить все интеграции без запуска polling:

```powershell
python preflight.py
```

Затем запустить бота:

```powershell
python bot.py
```

Команды бота:

- `/search <запрос>` — показать необработанные результаты Pinecone;
- `/status` — показать число векторов;
- `/help` — показать справку;
- обычное сообщение — получить ответ с найденным контекстом.

На одном токене Telegram может работать только один polling-процесс.

## Пять запросов для проверки

1. Какой проект помогает находить информацию по смыслу, а не по точным словам?
2. Где можно посмотреть мониторинг и анализ логов приложения?
3. Какой сервис автоматически разбирает обращения клиентов автосервиса?
4. В каком проекте бот умеет создавать QR-коды и хранить пользовательские файлы?
5. Какой проект показывает работу API в Docker-контейнере?

Фактические результаты появляются только после запуска `homework_demo.py` с рабочими ключами. В репозитории не используются придуманные ID или оценки сходства.

## Безопасность

- `.env` исключён из Git;
- реальные токены и API-ключи не выводятся в логи;
- в репозитории хранится только пустой `.env.example`;
- бот сообщает пользователю понятную ошибку, а техническая информация остаётся в локальном логе.

## Ограничения

Проект использует внешние сервисы Telegram, ProxyAPI и Pinecone. Без рабочих ключей доступны только офлайн-тесты и проверка структуры данных. Ответ языковой модели основан на пяти ближайших фактах, но релевантность результата всё равно нужно оценивать по ID, тексту и score из команды `/search`.
